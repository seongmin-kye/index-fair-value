# 시점별 구성 종목으로 SOXX 적정가 · 백테스트 — 설계

2026-11-02. 대상 저장소: `index-fair-value` (GitHub Pages 정적 페이지 + GitHub Actions 데이터 갱신).

## 의도

지금 SOXX 적정가는 **오늘의 구성 종목·비중**(`data/holdings/SOXX.json`, Zacks 에서 매주)을 과거 모든 달에
그대로 적용한다. 그래서 (1) 편입 전 종목이 과거 적정가에 들어가고, (2) 퇴출된 종목은 과거에서도 빠지며,
(3) NVDA·AVGO 처럼 비중이 크게 변한 종목이 과거 적정가를 지금 비중으로 왜곡한다. 백테스트 RMSE 와
그걸로 고르는 기준도 같은 오류 위에 서 있다.

이걸 **매달 T 에 실제로 SOXX 에 있던 종목과 비중**으로 계산하도록 바꾼다. 오늘 적정가는 지금 구성으로,
과거 적정가·백테스트는 그 시점 구성으로.

사용자가 정한 것:
- **주 방식은 종목별 합산.** 종목마다 자기 이력으로 고른 (n년, 백분위) 기준으로 적정가 ÷ 주가를 구하고,
  그 시점 비중으로 합친다. 종목별 기준은 바스켓과 무관하게 정해지므로 구성이 바뀌어도 그대로 쓸 수 있다.
- 지금의 **"지수 기준" 모드(종목 전체에 n·p 하나를 격자로 고름)는 없앤다.** 종목마다 다른 n·p 를 하나로
  뭉개는 근거가 약하다.
- 대신 **지수 수준 forward PER 비교선**을 둔다 (SOXX 전체의 이익수익률 → 지수 PER → 자기 과거 백분위).
  파라미터가 지수 하나에만 걸려 안정적이라, 종목별 합산과 백테스트 RMSE 를 나란히 보고 어느 쪽이 더 잘
  맞는지 확인하는 용도.
- 이력이 짧아 자기 기준을 못 정하는 종목은 지금처럼 **나머지 종목 목표 PER 중앙값**을 쓴다. 대신 매 시점
  "자기 기준으로 계산한 비중 / 빌린 기준 비중 / 중립 비중"을 기록해 페이지에 보여 준다.
- 시점별 구성은 **SEC N-PORT 공시(2019년 9월 말부터, 분기)** 로 받는다. 그 이전(N-Q 공시, HTML)은 이번 범위 밖.

## 목표 · 비목표 · 안티목표

목표
- 과거 매달의 SOXX 적정가와 백테스트가 그 달의 실제 구성·비중을 쓴다.
- 오늘·미래 적정가는 지금 구성(Zacks 매주)을 쓴다. 계산 규칙은 과거와 동일.
- SOXX 에 한 번이라도 있었던 종목(2019-09 이후)은 데이터가 있는 한 종목 파일을 갖고, 평일·토요일 갱신을 받는다.
- 종목별 합산과 지수 PER 비교선의 백테스트 RMSE 가 같은 달들 위에서 나란히 나온다.
- 매 시점 자기 기준·빌린 기준·중립 비중이 페이지에 보인다.
- N-PORT 신규 공시는 토요일 갱신에서 자동으로 받는다.

비목표
- QQQ·SPY 의 **비중**은 이번에 바꾸지 않는다 (여전히 현재 비중, 과거에도). 페이지에 그 사실을 적는다. 다음 차례.
  다만 모드는 SOXX 와 같아진다: 종목별 합산 + 지수 PER 비교선 (지수 기준 격자는 세 지수 모두 없앰). QQQ·SPY 는 비중이 고정이라
  지수 PER 시계열이 종목 이력만큼(2012년~) 있어 비교선도 5·10년 전체에 걸린다.
- 2019-09 이전 구성(N-Q 파싱)은 하지 않는다. 그 이전 달의 SOXX 적정가는 **없는 것으로 둔다** — 지금 비중으로
  되돌아가지 않는다.
- 종목별 n·p 를 고르는 `stockGrid` 가 백테스트 기간 전체를 보고 한 번 고르는 것은 그대로 둔다. 사용자 판단: 지금 시점에서 미래를
  예측하는 문제이므로 가능한 많은 데이터로 적합시키는 것이 맞다. 한계가 아니다.
- 과거 시점 컨센서스를 Wayback Machine(Yahoo analysis 페이지 스냅샷)에서 복원하는 일은 **다음 프로젝트**로 뺀다 (아래 8절).
- 퇴출되어 Yahoo·Zacks 에서 사라진 종목(아래 4개)의 주가·EPS 복원은 하지 않는다. 그 비중은 중립으로 넣고
  "중립 비중"에 드러낸다.
- SOXL 계산 방식은 바꾸지 않는다 (SOXX 적정가의 세제곱 그대로).

안티목표 (이러면 실패)
- 어떤 달이든 그 달에 SOXX 에 없던 종목이 적정가에 들어가는 것.
- N-PORT 를 못 받았거나 매핑이 안 된 종목이 있는데 페이지가 조용히 지금 비중으로 돌아가는 것. 못 받으면 빌드가
  실패하거나 페이지에 "이 구간은 구성 데이터 없음"이 보여야 한다.
- 백테스트 기간이 짧아졌는데(2019-09 이후) 사용자가 그걸 모른 채 "5년 · 10년" 라벨을 그대로 믿는 것.
- 페이지가 눈에 띄게 느려지는 것 (지금 빌드 약 0.4 MB, 브라우저에서 격자 계산).

  이걸 다 덮는다.** "10년" 은 2015-10 부터라 덮지 못한다.
- `fvView.basis` = `"index" | "sum"` 토글, `fvView.span` = 백테스트 5·10년, `fvView.range` = 차트 5·10년.

## 결정한 것

### 1. 데이터: N-PORT 분기 구성

- `python3 scripts/update.py nport` 를 추가. 시리즈 Atom 목록에서 NPORT-P 공시를 찾아 아직 없는 분기만 받아
  `data/holdings/SOXX/nport/{YYYY-MM-DD}.json` 에 저장 (분기말 날짜 = `repPdDate`). 행: `[ticker 또는 null, name, pct, shares, valUSD, id]`.
  `assetCat == "EC"` 만. 같은 티커가 두 행이면(분할 등) 합친다.
- ID → 티커는 `data/holdings/ids.json` (`{ "CUSIP 또는 ISIN": "TICKER" }`) 한 파일. 스크립트가 없는 ID 는 OpenFIGI 로
  채워 파일에 적고, 그래도 못 찾으면 **빌드가 아니라 갱신이 경고를 내고 그 행은 `ticker: null`** 로 둔다. 상장 폐지 4종목은
  빌더가 손으로 `ids.json` 에 넣는다 (티커는 적되 종목 파일은 없음 → 중립).
- SEC 요청의 `User-Agent` 는 환경변수 `SEC_UA` 가 있으면 그 값, 없으면 `index-fair-value (https://github.com/<owner>/index-fair-value)`
  (저장소 URL 이 연락처 역할; 개인 이메일을 공개 저장소에 넣지 않는다). 워크플로에 secret 배선은 하지 않는다 — 기본값으로 동작해야 하고,
  막히면 그때 `SEC_UA` secret 을 추가한다.
- OpenFIGI 결과가 지금 Zacks 구성(`data/holdings/SOXX.json`)의 종목명과 같은 회사를 가리키면 **Zacks 티커를 우선**한다. SK hynix ADR
  ISIN 이 OTC 티커로 매핑되어 `SKHY`(`000660.KS` 기반 frozen 파일) 와 비중이 갈라지는 것을 막기 위해서다. 매핑 결과는 어차피 `ids.json`
  에 남으므로 빌더가 손으로 고칠 수 있다.
- `nport` 뒤에 새 티커(파일 없음)는 기존 `holdings` 모드처럼 `update_full_one` 로 받는다. 이름이 바뀐 종목(AZTA, WOLF)은
  `ids.json` 에 지금 티커를 적는다.
- 워크플로: 토요일 `holdings` 다음에 `nport`. 실패해도 다른 단계는 진행 (지금 `holdings` 와 같은 태도).
- 현재 비중(`data/holdings/SOXX.json`, Zacks 매주)은 그대로 둔다. 오늘 계산용.

### 2. 월별 비중

- 달 T 의 비중: T 이하 마지막 N-PORT 분기말 Q 의 비중을 **주가로 굴린다**. `w_i(T) ∝ w_i(Q) × P_i(T) / P_i(Q)`,
  주식 비중 합이 Q 의 주식 비중 합과 같도록 정규화. 분기 사이에는 리밸런스가 없으니 시가총액 가중 바스켓이 실제로 이렇게 움직인다.
  주가가 없는 종목(중립 종목)은 Q 비중을 그대로 둔다. P_i(Q) 는 N-PORT 의 valUSD ÷ balance 가 아니라 종목 파일의 그 달 종가
  (일관성). 분기말 달의 종가가 없으면 굴리지 않고 Q 비중 그대로.
- 현금·선물 등 나머지(100 − 주식 비중 합)는 지금처럼 중립.
- 마지막 N-PORT 분기말 이후의 달(지금은 2026-07 ~ 오늘)은 **현재 Zacks 비중**을 쓴다. 이 달들은 EPS 가 안 확정돼 백테스트에
  안 들어가고, 차트의 "최근 12개월" 구간만 해당.
- 2019-09 이전 달: 비중 없음 → 적정가 null. 차트는 그 구간을 비워 두고 툴팁에 "구성 데이터 없음(2019-09 이전)".

### 3. 종목 집합과 합산

- `FV` 는 "2019-09 이후 N-PORT 에 한 번이라도 나온 티커 ∪ 지금 Zacks 구성" 중 종목 파일이 있는 것 전부. 각 종목은 더 이상
  고정 `w` 를 갖지 않고, `rawRatio(tg, ratioOf, T)` 가 `weightsAt(T)` 에서 그 달 비중을 받는다 (없으면 0).
  오늘·미래는 `weightsAt(ASOF_M)` = 현재 Zacks 비중.
- 종목 파일이 없는 티커(상장 폐지 4개)의 비중은 `weightsAt` 이 `neutral` 로 따로 돌려준다.
- 나머지 종목 중앙값(빌린 기준)은 **그 달 비중 > 0 인 종목들** 중 자기 기준이 있는 종목(8개 이상)으로 구한다. 메모리 규칙(MU 고점) 은 그대로.
- 매 T 마다 `own_w`(자기 n·p), `peer_w`(빌린 기준), `neutral_w`(중립: 데이터 없음·적자·현금) 를 같이 계산해 둔다.

### 4. 지수 PER 비교선 ("지수 기준" 모드를 대체)

- 달 T 의 지수 이익수익률 `EY(T) = Σ w_i(T)·E_i(T+12)/P_i(T) ÷ Σ w_i(T)`, 합은 ratio 를 계산할 수 있는 종목(비중 > 0,
  EPS > 0, 주가 있음)만. 지수 forward PER = 1/EY. 오늘은 `E_i` = NTM 컨센서스(`s.eN`), 미래 연도는 `s.path[y+1]` (종목별과 동일).
- 목표 지수 PER(T) = **T−12 까지 알 수 있는 지수 PER 전부의 중앙값** (최소 24개월, 격자 없음). 지수 PER(T) 는 T+12 의 EPS 를
  쓰므로 T 시점에 알 수 있는 관측은 T−12 까지다 (종목 규칙 `targetsAt` 의 `i ≤ T−12` 와 같은 원칙). 시계열이 2019-09 부터라
  비교선은 **2022-08 부터** (5년 백테스트 61개월 중 39개월). n·p 격자를 돌리기엔 창이 짧아 격자를 두지 않는다 — 비교선의 목적은
  "파라미터를 거의 안 쓴 안정적 기준"이므로 중앙값 하나면 된다.
- 적정가 = `P_SOXX(T) × 목표 PER / 지수 PER(T)`.
- UI: `fv-b-index` 버튼을 "지수 PER" 로 바꾸고 이 선을 보여 준다. 기본 모드는 "종목별 합산". **지수 기준 격자 표(`bt-thead`·`bt-tbody`)는
  없앤다.** 백테스트 카드에는 세 숫자: 종목별 합산 RMSE(5년 전체 달), 종목별 합산 RMSE(비교선이 있는 달만), 지수 PER RMSE(같은 달). 달 수와
  시작 달을 같이 적는다. 순위상관(`rho`) 문구는 종목별 합산 기준으로 유지.
- 종목별 기여(`fvContrib`)는 종목별 합산 기준으로만.
- `targetsAt`·`fillTargets`·`GRID`·`FV_N`·`FV_P` 와 `run_idx.js` 출력의 `n`·`p`·`cells`·`short` 는 지운다. `test_fv.js` 의 해당 테스트도 함께.

### 5. 백테스트 · 차트 구간

- `GRID_SPAN` 5년(2020-10 ~ 2025-10)은 그대로. 10년 옵션도 **`GRID_SPAN = 10` 그대로 돌리되**, 종목별 n·p 선택(`stockGrid`, 종목 자기
  이력 10년)은 그대로 하고 **지수 합산만 비중이 있는 달(2019-09 이후)로 제한**한다. 즉 SOXX 의 "10년" 백테스트 RMSE 는 2019-09 ~ 2025-10
  (약 74개월)로 계산되고, 버튼·문구는 "2019-09 ~" 로 표시한다. 2019-09 이전 달은 적정가 없음. `IDX_ALT["SOXX@10"]` 도 같은 규칙.
  QQQ·SPY 의 10년은 비중 고정이라 지금처럼 10년 전체.
- 종목별 n·p 를 고르는 `stockGrid` 는 바꾸지 않는다.

### 6. 페이지에 보이는 것

- 요약 줄: "지금 구성 N종목(비중 x%), 자기 기준 a% · 빌린 기준 b% · 중립 c%". 과거 달 툴팁에도 그 달의 a·b·c 와 구성 종목 수.
- 설명 항목에 추가: 과거 비중은 SEC N-PORT 분기 공시를 주가로 굴린 것, 2019-09 이전 없음, 상장 폐지 4종목 중립, QQQ·SPY 는 아직 현재 비중,
  종목별 n·p 선택의 미래 참조.
- 기존 "비중은 과거에도 지금 비중" 문구 삭제.

### 6b. 과거 구성 종목의 노출

- `DATA`(→ `FV`) 에는 과거 구성 종목 13개도 들어가지만, **종목별 섹션의 칩(`SFV_LIST`)과 맨 아래 원자료 표에는 지금 비중 > 0 인 종목만**
  보인다 (`FV_X` 의 삼성전자는 지금처럼). `sfvPeer`(오늘 기준 나머지 종목 중앙값) 의 모집단도 지금 비중 > 0 인 종목.
  페이지는 종목당 3~4 KB 씩 약 50 KB 커지는데 허용 범위.

### 7. 빌드

- `build.py` 가 `SOXX_W_HIST = { "2019-09-30": { "TICKER": pct, … , "_neutral": pct }, … }` 한 줄을 페이지에 넣는다. 월별 굴리기는 페이지 JS 에서
  (run_idx.js 도 같은 코드를 돌리므로 한 곳에만 있으면 된다). `DATA` 는 종목 집합 전체 (지금 비중은 `w`, 없으면 0).
- `run_idx.js` 의 QQQ·SPY 경로는 `SOXX_W_HIST` 가 없을 때 지금처럼 `DATA[].w` 고정 비중으로 동작해야 한다 (QQQ·SPY 비목표).

### 8. 과거 적정가의 EPS 미래 참조 완화

문제. 과거 T 의 적정가 = 목표 PER × **E(T+12) 실제값**이다. T 시점 투자자는 그 값을 몰랐고 컨센서스만 알았다. 그래서 (a) 백테스트 RMSE 가
실제 운용보다 좋게 나오고, (b) 목표 PER 은 "주가 ÷ 실제 EPS" 분포에서 나오는데 오늘 적정가는 그 목표 PER 에 **컨센서스** EPS 를 곱하므로
컨센서스의 편향이 오늘 적정가에 그대로 들어간다. 과거 컨센서스 기록이 이 저장소에 없고(저장소는 2026-10-28 시작) 무료 API 에도 없다.

크기 (스파이크로 잼, 지금 페이지 코드 · 지금 비중 기준, 5년 백테스트):

| 과거 적정가의 EPS | 지수 기준 RMSE | 종목별 합산 RMSE |
|---|---|---|
| V0 실제값 E(T+12) (지금) | 14.8% | 14.9% |
| V1 T 시점 단순 예측 = TTM(T) × (1 + 직전 3년 실현 NTM 성장률 중앙값), 목표 PER 은 V0 그대로 | 25.8% | 25.0% |
| V2 단순 예측, 목표 PER 도 단순 예측 기준으로 | 29.4% | 28.8% |

컨센서스 기준의 정직한 RMSE 는 V0 과 V1 사이 어딘가다 (컨센서스는 보통 단순 외삽보다 낫고 실제값보다 못하다). 즉 지금 보이는 14.9% 의 상당 부분은
미래 EPS 를 안 덕이다. 스파이크 스크립트: 이 세션의 scratchpad `spike/foresight.js` (버릴 것, 빌더는 같은 치환을 페이지 코드 안에 정식으로 넣는다).

이번에 하는 것 (사용자 판단: 대표 방식은 하나 — 지금 방식. 오늘 EPS 추정치로는 컨센서스가 단순 외삽보다 낫다. 차트를 늘리지 않는다):

- **8a. 설명 한 문장.** 빌드가 V1(단순 예측: `FWD(s, T) = TTM(T) × (1 + clamp(median(직전 36개월의 실현 NTM 성장률), −50%, +50%))`,
  관측 12개월 미만이면 그 종목 중립, 목표 PER 은 그대로) 의 종목별 합산 RMSE 를 한 번 계산해 백테스트 카드의 설명 문장에 숫자로 넣는다:
  "과거 적정가는 12개월 뒤 실제 EPS 기준. T 시점에 알 수 있던 단순 예측으로 바꾸면 RMSE 약 N% — 컨센서스 기준은 그 사이". 차트·선·토글·표 열은
  추가하지 않는다. `IDX_ALT` 에도 지수마다 이 숫자 하나(`fwdErr`)만 더 넣는다.
- **8b. 컨센서스 기록 시작.** `update.py full` 이 끝날 때마다 `data/consensus/{YYYY-MM-DD}.json` 에 종목별 `{ntm: NTM EPS, fy: [[fy, eps 평균], …]}`
  를 저장한다 (한 달에 첫 토요일 것만 남기고 나머지는 덮어씀 → 월 1개). 페이지는 이걸 쓰지 않는다. 12개월이 쌓이면 "그 시점 컨센서스 기준"
  백테스트를 추가할 수 있다. 파일 크기는 종목당 수십 바이트.

다음 프로젝트 (이번 범위 밖, 확인된 사실만 적음):

- Wayback Machine 에 `finance.yahoo.com/quote/{T}/analysis` 스냅샷이 있다. 2023년 이전은 페이지 안의 JSON(`"earningsTrend":{"trend":[{"period":"0q",…`,
  `earningsEstimate.avg`), 2024년 이후는 HTML 표(`Avg. Estimate` 행: 이번 분기 · 다음 분기 · 올해 · 내년) — 두 형식. 월 단위로 뭉친 스냅샷 수:
  NVDA 41, AMD 36, TSM 22, MU 21, QCOM 15, AVGO 14, ASML 11, TXN 6, XLNX 1 (2019~2026). 드문드문이라 월별 백테스트엔 모자라지만,
  "그 시점 컨센서스 NTM ÷ 12개월 뒤 실제" 의 분포(반도체 컨센서스 편향)를 재기엔 수십 개 점이 나온다. `finance.yahoo.com/quote/NVDA` 메인 페이지는
  90개월치가 있는데 추정치가 들어 있는지는 확인 안 함.
- 그 결과로 (1) 백테스트 RMSE 가 V0~V1 사이 어디인지 점 추정, (2) 오늘 컨센서스 EPS 에 곱할 편향 보정 계수(종목별 또는 반도체 공통)를 낼 수 있다.

## 빌더에게 맡기는 것

- JSON 의 정확한 모양, 함수 이름, 페이지 문구.
- N-PORT 파싱 방식(정규식이든 `xml.etree` 든), OpenFIGI 호출 묶음 크기와 재시도.
- 검증 방법. 최소한: (1) `update.py nport` 뒤 28개 분기 파일, 각 분기 주식 비중 합 95~101%, 매핑 안 된 행 목록 출력,
  (2) `build.py` 뒤 node 로 백테스트가 돌고 `SOXX@10` 이 2019-09 부터 시작, (3) 2021-09 달의 비중에 XLNX 가 중립으로 들어가고
  ALAB 은 0 인 것, (4) 오늘 적정가가 현재 Zacks 비중으로 계산되는 것(합이 99.9%).
- 새 종목 파일 13개를 받는 순서와 시간(Zacks 호출 각 1초 간격).
- 브라우저 성능: 종목 수가 31 → 약 44 로 늘고 월별 비중 계산이 추가된다. 느려지면 월별 비중을 빌드에서 미리 계산해 넣는 것도 가능.

## 한계 (페이지에 적을 것)

- 과거 비중은 분기말 공시를 주가로 굴린 근사. 분기 중 편입·퇴출은 다음 분기말에 반영된다.
- 2019-09 이전은 구성 데이터가 없어 적정가를 계산하지 않는다.
- 상장 폐지 4종목(XLNX·MXIM·IPHI·CCMP)은 중립. 2020~2021년에 합쳐 최대 약 7%.
- 과거 적정가는 12개월 뒤 실제 EPS 로 계산한 것(실제값 기준). T 시점에 알 수 있던 단순 예측으로 바꾸면 RMSE 가 약 15% → 25% 로 커진다.
  컨센서스 기준은 그 사이. 과거 컨센서스 기록은 2026-11 부터 쌓기 시작.
- QQQ·SPY 는 아직 현재 비중.
- 지수 PER 비교선은 2022-08 부터만 (지수 PER 이력 2년 + EPS 확정 12개월).
